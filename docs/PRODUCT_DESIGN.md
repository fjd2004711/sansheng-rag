# 产品设计说明

目标用户：不懂技术、看重"靠不靠谱"的人（例如在校教师）。核心承诺：**每个回答都能查证，每次纠错都看得见。**

## 调研：成熟产品怎么做

| 来源 | 可借鉴的做法 |
|---|---|
| [Perplexity 设计拆解](https://www.925studios.co/blog/perplexity-design-breakdown) | 先给答案，再给来源，再给追问；行内编号引用，悬停即见出处；核对永远不是强制的，但始终一步可达（渐进披露）；批评：所有来源卡片看起来一样可信、手机上拥挤 |
| [NotebookLM 三栏设计（Google 官方博客）](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-new-features-december-2024/) | 资料、对话、产出分栏；点击引用直达原文段落；用户随时能看到并选择"系统依据的是哪些资料" |
| [People + AI Guidebook：可解释性与信任](https://pair.withgoogle.com/chapter/People%20+%20AI%20Guidebook%20-%20Explainability%20+%20Trust.pdf) | 目标是**校准**信任而不是最大化信任：让用户知道何时该信、何时该自己判断；解释要追求"理解"而非"完整" |
| [Microsoft HAX：人机交互 18 条准则](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) | 第 1 条：讲清楚系统能做什么（简介、示例输入/输出）；第 11 条：讲清楚系统为什么这么做 |
| [AI UX 模式总结](https://www.lazarev.agency/articles/ai-ux-patterns) | 反模式：沉默的转圈（30 秒像坏了）、一律不留余地的断言、无来源、编造或死胡同式的失败、空白输入框；失败/慢/不确定要当作正常状态来设计；失败时给下一步出路 |

## 对照：改造前的问题 → 设计决策

| 改造前 | 问题（对应的原则） | 现在 |
|---|---|---|
| 回答要等核对结束才出，期间只有一张检索卡片 | 沉默的转圈 | 实时进度行，按运作流程的最新一步说明系统正在做什么 |
| 运作流程只显示最新一条，刷新就没了 | 无法回看"为什么这么答" | 每条回答独立保存流程（`messages.agent_trace`）；回答下方"查看运作流程"切换面板，面板标明针对哪个问题 |
| 看不出回答可不可信 | 信任没有校准 | 每条回答下一条核对结论：已核对 / 纠错后通过 / 仅部分有依据 / 没有找到答案 |
| 查不到只有一句话 | 死胡同式失败 | 拒答卡片：列出已试过的检索，给出"换个说法""请管理员补充资料"的下一步 |
| 只能答一半时整题拒答 | 丢掉有用的部分 | 部分回答：有依据的内容照给，缺的明确说明 |
| `[1]` 点开才知道是什么 | 核对成本高 | 悬停显示文件名与原文片段，点击打开来源面板 |
| 不知道系统依据什么回答 | 范围不清（HAX-1） | 输入框下方"回答依据：N 份资料"，点开是文件列表；空状态写明能做/不能做 |
| 空白对话框 | 空输入框 | 4 个点选即问的示例；回答后给 2～3 个"接下来可以问" |

## 信息层次（一条回答）

1. 回答正文，行内编号引用
2. 核对结论条（一句话 + "查看运作流程"）
3. 依据入口（"查看 N 处依据"）
4. 接下来可以问（仅最后一条回答）

运作流程面板是"想看才看"的第二层：窄屏（< 1024px）不显示，核对结论条仍在。

## 已知取舍与待办

- 核对结论只用定性文字，不显示百分比：`有据可查 59%` 这类数字对非技术用户反而造成困惑，百分比保留在运作流程节点里。
- 追问建议由模型基于本次检索到的资料生成，异步发送，不阻塞下一个问题；失败时静默不显示。
- 待办：窄屏下用抽屉展示运作流程；来源按可信度分级显示（目前所有来源样式一致，Perplexity 同样被批评过）；点击引用时在原文中高亮对应段落；对回答的"有用/没用"反馈。
